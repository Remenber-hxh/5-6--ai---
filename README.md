# 智巡 InspectAI

> 把"拍照 → AI 识别字段 → 人工确认 → 提交日报 → 沉淀资产台账"串成一条闭环的设施巡检 SaaS。
>
> **新员工第一天上岗，3 张照片 10 秒生成合规日报；漏拍 AI 主动报警；主管手机 30 秒批掉；台账自动累计、AI 帮主管比对历史趋势。**

---

## 一句话定位

**面向中小型设施运维团队**（物业 / 园区 / 楼宇）**的「拍照即完成」巡检平台**。
传统巡检员带夹板对着 10 多项检查要点逐条核对、抄写、签字，单次 20-30 分钟；智巡让 AI 完成识字、填表、判异常、给行动建议，巡检员只负责拍照和确认，单次缩到 1-2 分钟。

---

## 演示场景

**HYZX-WJ-DT01 无机房电梯**（DEMO.md 中完整 9 幕脚本）：

1. 新巡检员张三对电梯拍 3-4 张照片（**故意不拍按钮面板**）
2. AI 10 秒：识别为电梯巡检 → 调出对应模板 → 自动预填编号 → 11 项检查要点全部自动选「正常 / 完好」
3. 「按钮与显示」字段被 AI 主动标为**异常**："按钮指示灯未覆盖，请补拍按钮面板"——漏检兜底
4. 提交后 AI 给行动建议："立即处理 — 按钮面板正面特写，优先级高"
5. 申请修改 + 补传照片 → 主管手机收红点 → 30 秒审批通过
6. 主管打开资产台账，HYZX-WJ-DT01 自动关联到这次巡检，导出 CSV 给上级

完整剧本：[`docs/DEMO.md`](docs/DEMO.md)

## 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Go 1.24 (stdlib + go-sql-driver) | 单二进制部署，无 runtime 依赖 |
| AI 微服务 | Python 3.13 (stdlib + subprocess curl) | 国内连 DashScope 走 curl 比 urllib 稳 |
| AI 模型 | Qwen-VL Plus / Qwen Plus (DashScope) | 国内可用，多模态识别强 |
| 前端 | 原生 JS + CSS (零依赖) | 无构建步骤，改即生效，部署体积小 |
| 数据库 | MySQL 8 / SQLite 3 | 生产用 MySQL，本地 SQLite 零配置 |
| 反向代理 | nginx alpine | 业界标准 |
| 容器编排 | Docker Compose v2 | 单机够用，云原生迁移成本低 |
| 密钥管理 | Windows DPAPI / Docker Secret | 不允许明文落盘 |

## 当前版本能力 (v1.0)

### 移动端（巡检员视角）

- [x] **AI 场景自动识别**：上传照片 → 自动判断是水表/电表/电梯/消防泵/UPS 等 10 种场景之一 → 调出对应模板
- [x] **AI 字段提取**：照片里能看清楚的数值/状态/读数 → AI 直接填进表单字段
- [x] **保守判断 + 漏检兜底**：照片不足时 AI 不强行填，标"需人工复核"；关键照片缺失时主动报警
- [x] **手机扫码/快门拍照**：调用浏览器原生相机
- [x] **离线缓存**：照片先存本地，网络回来后批量上传
- [x] **本周小记**：今日已巡检几条 / 还有几条待办，激励反馈

### 管理后台（主管视角）

- [x] **首页一屏总览**：今日 AI 交付几条 / 待处理 / 准确率 / AI 智能问答
- [x] **巡检计划**：每日 / 每周 / 每月节奏 + 责任人指派 + 自动派生任务
- [x] **巡检任务**：开始 / 完成 / 闭环 + 完成统计沉到个人工作台
- [x] **巡检记录**：所有日报全档案，支持多维筛选
- [x] **资产台账**：每台设备的"活档"，自动关联历史巡检记录
- [x] **设备管理**：主数据增删改 + 点位绑定
- [x] **异常复核**：AI 报的异常进队列给人复核 + 给出复核建议
- [x] **修改审批**：巡检员申请改记录 → 主管批 → 自动留痕
- [x] **数据看板**：5 种时间维度 (今日/本周/本月/本季/全部) + 准确率 + 闭环率 + 类型分布
- [x] **AI 智能问答**：千问 Plus 驱动，主管自然语言提问，AI 拿系统实时数据回答

### 后端能力

- [x] **多模板支持**：内置 10 套巡检模板（紫涵雅集能耗 / 综合巡检 / 热水机房 / 消防泵 / UPS / 变电所 / 生活水泵 / 扶梯 / 无机房电梯 / 有机房电梯）
- [x] **字段级元数据**：required / source (AI/manual) / Default (预填) / Kind (text/number/choice)
- [x] **同义词归一化**：AI 输出"无问题"自动转"正常"
- [x] **正向选项 fallback**：AI 失败时按字段定义的最佳选项兜底
- [x] **审计链不可篡改**：所有改动走"申请 → 审批"，原值保留
- [x] **资产去重**：同 project + template + asset_no 自动归一到同一台设备活档
- [x] **图片 TTL 清理**：临时分类用图 24 小时自动删

### 部署能力

- [x] **本地开发**：PowerShell 一键启 (`scripts/start-local.ps1`)
- [x] **Docker Compose 生产部署**：MySQL + AI + Backend + Admin + nginx 全套
- [x] **Docker Secret 装密钥**：DASHSCOPE_API_KEY / MySQL 密码全部走 `/run/secrets/*`
- [x] **镜像版本化**：build 自动用 git short-sha 当 tag，支持 registry push / 回滚
- [x] **完整 healthcheck**：4 个服务全部探活，nginx 等就绪才接流量
- [x] **部署文档**：[`inspectai/docs/DEPLOY.md`](inspectai/docs/DEPLOY.md) 含 secret 准备 / 备份 / 轮换 / 排错

## 还没做的事 (Roadmap)

### 短期 (1-2 月内)

- [ ] **审批通过状态联动**：主管通过修改后，记录状态没自动从"异常"刷回"正常"，得手动刷
- [ ] **AI 行动建议 UI 突出**：建议存在但页面上不够显眼，新巡检员可能忽略
- [ ] **微信扫码登录**：现在还是账号密码，企业微信 OAuth 已留接口，待接入
- [ ] **多语言**：i18n 还没拆，固定中文
- [ ] **移动端 PWA**：已支持离线缓存，但还没做 Service Worker 安装到桌面

### 中期 (3-6 月)

- [ ] **租户隔离**：现在是单组织，多客户共用需加 tenant 字段
- [ ] **SSO**：钉钉 / 飞书 / 企业微信单点登录
- [ ] **RBAC 精细权限**：现在只分巡检员 / 主管，要加部门 / 项目级权限
- [ ] **巡检路径优化**：基于设备位置 + 上次巡检时间，AI 给最优巡检顺序
- [ ] **设备故障预测**：基于历史读数趋势 (电表度数 / 温度) 预警"快要超阈值"
- [ ] **报表自定义**：主管可配置自己关心的 KPI 卡片

### 长期 (>6 月)

- [ ] **本地化模型**：千问 7B 本地部署，敏感场景不出公网
- [ ] **多模态扩展**：语音录入 / 现场视频抽帧识别
- [ ] **数字孪生 BIM 集成**：和建筑 BIM 模型联动，巡检数据直接挂在 3D 模型上
- [ ] **IoT 协议接入**：直接读传感器数据 (Modbus / MQTT)，AI 只校验异常
- [ ] **小程序版**：原生微信小程序，绕开浏览器权限麻烦
- [ ] **OpenAPI**：开放 API 给第三方 ERP / OA 集成

### 工程债

- [ ] **测试覆盖**：单测 / E2E 都偏薄，重构容易翻车
- [ ] **CI/CD**：GitHub Actions 自动 build/push 镜像还没配
- [ ] **监控告警**：缺 Prometheus / Grafana / Sentry
- [ ] **日志结构化**：现在是文本 log，要切 JSON + 接 ELK
- [ ] **图片对象存储**：现在存本地磁盘，要切 OSS / S3
- [ ] **MySQL 备份自动化**：DEPLOY.md 给了命令，但没 cron job

## 未来愿景

### 三年看：AI 驱动的"设施全生命周期"管理平台

巡检只是入口。每一次巡检沉淀的"设备状态时间序列"是宝藏：

1. **从巡检 → 维保**：AI 在巡检中看到趋势变化，主动派工"该换滤芯了"
2. **从维保 → 资产管理**：每台设备的健康度评分、剩余寿命、采购建议
3. **从单设备 → 整楼宇**：能耗趋势 + 设备健康 + 空间利用率 = 楼宇综合运营仪表盘
4. **从单楼宇 → 多园区**：连锁物业一屏看所有项目，AI 跨项目对比"哪个园区效率最高"

### 五年看：行业 AI 中台

把"设施巡检"垂直行业 know-how（10 套模板背后的检查要点、各类设备的异常判定规则、行业法规要求）沉淀成「**行业 prompt 库 + 行业模型**」，让任何物业公司 30 分钟就能接入一个为自己定制过的 AI 巡检助手。

### 一句话

**让 AI 把那些"该做但人记不住、做了但没留痕"的运维细活，全部自动接管。**

## 快速开始

### 本地开发

详见 [`inspectai/README.md`](inspectai/README.md)。简版：

```powershell
cd inspectai
.\scripts\setup-key.ps1   # 一次性：交互输入 DASHSCOPE_API_KEY，DPAPI 加密落 .env.secure
.\scripts\start-local.ps1 # 启 Go 后端 (18080) + Python AI (19100)
.\scripts\start-admin.ps1 # 启管理后台静态服务 (18081)
```

访问：
- 移动端：http://127.0.0.1:18080
- 管理后台：http://127.0.0.1:18081

### 生产部署

详见 [`inspectai/docs/DEPLOY.md`](inspectai/docs/DEPLOY.md)。简版（Linux + Docker）：

```bash
git clone https://github.com/Remenber-hxh/5-6--ai---.git
cd 5-6--ai---/inspectai
cp .env.prod.example .env.prod
# 编辑 .env.prod 填非敏感配置

export DASHSCOPE_API_KEY=sk-xxx MYSQL_PASSWORD=xxx MYSQL_ROOT_PASSWORD=xxx INSPECTAI_ADMIN_PASSWORD=xxx
bash scripts/prepare-secrets.sh

docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```
