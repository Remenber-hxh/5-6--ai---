# 第一版方案总览

## 1. 核心业务闭环

```text
选点位
  └─ 拍照（多张，可调摄像头/相册）
      └─ 上传 → 千问 VL 识别
          ├─ 识别成功 → 自动填充字段 → 进入【字段确认页】
          └─ 识别失败 → 弹窗"无法识别，请重新拍摄"
              ├─ 第 1、2 次失败：返回拍照页
              └─ 第 3 次失败：跳【手动填写页】
【字段确认页】用户逐项核对/修改 → 提交
  └─ 后端冻结字段（人工修正即最终版，AI 不再覆盖）
      └─ 后端调千问做"总结生成"（输入：最终字段 + 原图）
          └─ 总结作为新字段 `aiSummary` 追加，不覆盖任何原字段
              └─ 入库 + 归集进【资产台账】
                  └─ 返回成功 + 显示企业微信日报样式预览
```

## 2. 与上一版（mock 演示）的差异

| 维度 | 旧版 | 新版（本次扩展） |
| --- | --- | --- |
| 识别 | mock，固定返回 | 真实千问 VL（qwen-vl-max / qwen-vl-plus），mock 留作降级 |
| 失败处理 | 不区分，直接进检查项页 | 弹窗 → 重拍 → 3 次后进手动填写 |
| 字段 | 4 个固定 checkItems | 按表单类型动态生成（10 套 schema） |
| 修正后逻辑 | 改了就改了 | 修正字段冻结 + AI 单独生成总结追加 |
| 台账 | 无 | 资产维度归集（按"机房编号 / 电梯编号 / 巡检地点"） |
| 终端 | PC 演示页 | 移动端 first，PC 视为大屏移动端 |
| API 安全 | 默认 mock | 真实 key 写 `.env`，不入代码不入文档（key 已在对话曝光，建议 demo 后到阿里云后台轮换） |

## 3. 识别失败的判定标准（重拍触发条件）

任意一条命中即视为"识别失败"，弹窗提示重拍：

1. 千问调用 HTTP 失败 / 5xx / 超时（>20s）。
2. 返回 JSON 解析失败 或 `extractedFields` 为空对象。
3. 图片质量分 `<0.4`，或 `isBlurry=true / isOverExposed=true`。
4. 与点位严重不匹配：`detectedScene` 与点位类型相似度 `<0.3`（如选了"UPS机房"但识别出"室外景观"）。
5. 关键字段全部为 null（每张表 schema 里标注 1-3 个"关键字段"，全空才判失败，半空仍然进确认页）。

每张记录的失败计数保存在 `record.retryCount`，到 3 后端口返回 `{ "action": "manual_fallback" }`，前端跳手动填写页。

## 4. 人工修正与 AI 总结的关系

- 字段层：人工提交后冻结。后端落库时打 `fieldsLockedBy: "human"` 标记，AI 二次调用不再修改任何确认字段。
- 总结层：后端把"最终字段 JSON + 图片 URL + 表单类型"作为提示词喂给千问，要求只输出一段自然语言总结（300 字内，发企业微信群的口吻）。
- 总结结果存到 `record.aiSummary`，独立字段，UI 上展示在"日报预览"卡片底部，标注【AI 总结】，便于人工识别归责。
- 如果用户对总结不满意可手动改 `aiSummary`（也可以加"重新生成"按钮，复用同一 prompt）。

## 5. 资产台账（Asset Ledger）

10 张表里"资产维度"的字段：

| 表单 | 资产编号字段 | 自然分组 |
| --- | --- | --- |
| UPS机房巡检报批 | `UPS机房编号` 1-5 | UPS 主机 ×5 |
| 变电所巡检报批 | `变电所编号` 1-3 | 变电所 ×3 |
| 消防泵巡检报批 | （单点） | 消防泵房 ×1 |
| 热水机房巡检报批 | （单点） | 热水机房 ×1 |
| 生活水泵巡检报批 | （单点） | 生活水泵房 ×1 |
| 扶梯巡检 | `电梯编号` | 扶梯 N（待你给清单） |
| 电梯巡检（无机房） | `电梯编号` | 无机房电梯 N |
| 电梯巡检（有机房） | `电梯编号` | 有机房电梯 N |
| 紫涵雅集每日综合巡检 | `巡检地点` | 紫涵雅集（综合）×1 |
| 紫涵雅集能耗抄表 | `巡检地点` | 紫涵雅集能耗 ×1 |

台账两张表：

```text
assets
  id            主键（系统生成）
  code          资产编号（如 UPS-1、变电所-3、扶梯-A12345678）
  type          资产类型（ups / substation / fire_pump / hot_water / life_pump /
                escalator / elevator_no_room / elevator_with_room / energy_meter ...）
  project       会议中心 / 紫涵雅集
  location      物理位置
  bindingForm   该资产对应的巡检表单 ID
  createdAt

inspection_logs
  id            主键
  assetId       外键 → assets.id
  recordId      外键 → records.id（巡检记录）
  inspectorName
  inspectedAt
  status        normal / abnormal / review
  keyFields     JSON，关键字段快照（电压/水位/温度等）
  aiSummary     AI 总结
  photos        图片 URL 数组
```

提交记录时按"资产编号 + 表单类型"自动 upsert 到 `assets`，并写一条 `inspection_logs`。台账页可按资产筛选、查看历史。

## 6. 千问 VL 接入

### 6.1 使用模型
- 主模型：`qwen-vl-max`（高精度，演示用）。
- 降级：`qwen-vl-plus`（响应快、便宜，作为前端首次调用）；再次失败回 mock。
- 总结模型：`qwen-plus`（纯文本，便宜）。

### 6.2 API key
- 写到 `inspectai/.env`（`.gitignore` 已含 `.env`）：
  ```env
  AI_PROVIDER=dashscope
  DASHSCOPE_API_KEY=sk-xxxxxxxx
  DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
  QWEN_VISION_MODEL=qwen-vl-max
  QWEN_VISION_FALLBACK=qwen-vl-plus
  QWEN_TEXT_MODEL=qwen-plus
  ```
- **重要**：你贴在对话里的那串 key 已经明文出现在聊天历史，演示完到阿里云控制台轮换一次。
- 现在仅写到本地 `.env`，不写进任何 md / 代码 / commit。

### 6.3 调用结构
- 由 Python `ai-service` 包一层（隔离 SDK 升级 + 集中改 prompt）。
- Go 后端只跟 `ai-service` 通信，不直连阿里云。
- prompt 模板按表单类型分文件存 `ai-service/prompts/{form_type}.txt`，方便逐表调优。

### 6.4 输出 schema 强约束
- prompt 末尾强制要求 JSON 输出，schema 跟前端字段一一对应（用 dashscope 的 JSON mode 或 prompt 内 schema 描述）。
- 解析失败重试 1 次，再失败计入"识别失败"。

## 7. 移动端

- 前端按移动 first 重写：vw 单位 + `max-width: 480px` 居中（PC 上看也不丑）。
- 拍照：`<input type="file" accept="image/*" capture="environment">`，浏览器自动调起后置摄像头。
- 关键交互：底部 sticky 主按钮、单列表单、可折叠卡片、所有按钮触摸目标 ≥44pt。
- 失败弹窗：全屏遮罩 + 大字 + 单"重拍"按钮，不让用户误触。
- 第 3 次失败转手动填写时，弹窗文案改为"识别多次未成功，请手动填写"+ 默认值用上一次同点位的最近一条记录预填（减少手填工作量）。

## 8. 数据持久化

- 第一版用 SQLite（`storage/inspectai.db`）替换 in-memory store。两天能做、零部署成本。
- 三张核心表：`records / assets / inspection_logs`；图片仍存文件系统 `storage/uploads/{recordId}/`。
- 升级到 PostgreSQL 在 v2，schema 可平滑迁移。

## 10. 不做的事（明确边界）

- 企业微信原生消息推送 / 审批接入 — 演示截图代替。
- 离线巡检、PWA 缓存。
- 设备资产身份识别（"这是不是 UPS-3 号机"）— 资产编号靠人工选 / 二维码扫，不靠图像识别。
- 自动派工、抄送审批人。
