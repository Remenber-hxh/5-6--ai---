# 云服务器迁移准备方案

## 1. 当前迁移判断

当前 `inspectai/` 版本已经具备迁移到云服务器做演示版的基础：

- Go 后端已拆分为独立服务，负责前端静态页、业务 API、巡检记录、台账和 AI 任务。
- Python AI 服务已独立运行，提供 `/classify`、`/analyze`、`/summarize`。
- 前端已改为移动端优先，适合企业微信入口打开。
- 已有 `docker-compose.yml`、`go-backend/Dockerfile`、`ai-service/Dockerfile`、`nginx/nginx.conf`。
- 当前存储已接入 SQLite，并保存上传图片到 `storage/uploads/`。

结论：

- **演示版迁移难度：中等偏低**。一台云服务器 + Docker Compose + HTTPS 域名可以跑。
- **正式生产版迁移难度：中等**。还需要补鉴权、台账编辑、数据备份、日志、对象存储、密钥管理等。

当前不建议继续用 Windows 本地脚本作为云端部署方式，云端建议统一走 Linux + Docker Compose。

## 2. 推荐云端架构

```text
企业微信入口
   ↓ HTTPS 域名
Nginx 反向代理
   ↓
Go 后端 + 前端静态页  :8080
   ↓
Python AI 服务       :9100
   ↓
千问 DashScope API
   ↓
SQLite / 后续 PostgreSQL
   ↓
本地 uploads / 后续 OSS
```

第一阶段先做单机部署，不拆太复杂：

- `nginx`：负责 HTTPS、反向代理、企业微信可信域名校验文件。
- `go-backend`：负责业务 API、前端页面、巡检记录、台账、文件管理。
- `ai-service`：负责千问视觉识别、场景分类、AI 总结和建议。
- `storage/`：挂载到云服务器磁盘，保存 SQLite 数据库和上传图片。

## 3. 云服务器准备

建议最低配置：

- CPU：2 核起
- 内存：4 GB 起
- 系统：Ubuntu 22.04 / Debian 12 / Alibaba Cloud Linux 均可
- 磁盘：40 GB 起，图片较多时建议单独挂数据盘

需要安装：

- Docker
- Docker Compose
- Nginx 或使用 compose 内的 nginx 容器
- Certbot 或云厂商证书管理

开放端口：

- `80`：HTTP 证书申请 / 跳转 HTTPS
- `443`：企业微信访问入口
- `8080`、`9100` 不建议公网暴露，只允许容器内部访问

## 4. 域名和 HTTPS

企业微信要求可信域名必须是 HTTPS。

需要准备：

- 一个正式域名，例如 `inspectai.example.com`
- DNS A 记录解析到云服务器公网 IP
- HTTPS 证书
- 企业微信可信域名校验文件

Nginx 需要支持：

- `/` 反向代理到 Go 后端
- 企业微信校验文件可以直接访问
- 上传图片大小限制，例如 `client_max_body_size 50m`

## 5. 环境变量迁移

当前本地使用 `.env` + `.env.secure`，其中 `.env.secure` 依赖 Windows DPAPI。

云服务器是 Linux，**不能直接迁移 `.env.secure`**。

云端建议改为以下方式之一：

1. 使用 `.env.production`，只放在服务器本地，不提交代码。
2. 使用云厂商密钥管理服务。
3. 使用 Docker Compose 的 `env_file` 或容器编排平台 Secret。

生产/演示环境建议变量：

```env
DEMO_MODE=false
AI_PROVIDER=qwen

DASHSCOPE_API_KEY=你的DashScope密钥
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_VISION_MODEL=qwen-vl-plus
QWEN_TEXT_MODEL=qwen-plus

BACKEND_ADDR=:8080
AI_SERVICE_URL=http://ai-service:9100
AI_SERVICE_ADDR=0.0.0.0
AI_SERVICE_PORT=9100

FRONTEND_DIR=/app/frontend
STORAGE_DIR=/app/storage
SQLITE_PATH=/app/storage/inspectai.db
```

注意：

- `DASHSCOPE_API_KEY` 不要写进文档、代码或镜像。
- 本地演示用的 `AI_PROVIDER=mock` 不应作为云端默认值。
- 演示环境也建议 `DEMO_MODE=false`，否则领导看到的数据价值会打折。

## 6. Docker Compose 需要调整

当前 `docker-compose.yml` 默认还是：

```yaml
DEMO_MODE: "true"
AI_PROVIDER: "mock"
```

迁移前建议改为：

- 使用 `env_file: .env.production`
- 不在 compose 文件里明文写 key
- `go-backend` 和 `ai-service` 只暴露给内部网络
- 只让 `nginx` 暴露 80/443

建议结构：

```yaml
services:
  ai-service:
    build:
      context: .
      dockerfile: ai-service/Dockerfile
    env_file:
      - .env.production
    expose:
      - "9100"

  go-backend:
    build:
      context: .
      dockerfile: go-backend/Dockerfile
    env_file:
      - .env.production
    volumes:
      - ./storage:/app/storage
    expose:
      - "8080"
    depends_on:
      - ai-service

  nginx:
    image: nginx:1.27-alpine
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/cert:/etc/nginx/cert:ro
      - ./nginx/wework-verify:/usr/share/nginx/html/wework-verify:ro
    ports:
      - "80:80"
      - "443:443"
    depends_on:
      - go-backend
```

## 7. AI 服务镜像风险

当前 `ai-service/run.py` 通过 `curl` 调用 DashScope。

`ai-service/Dockerfile` 当前基于 `python:3.13-slim`，但没有显式安装 `curl` 和 CA 证书。

迁移前建议修改 Dockerfile：

```dockerfile
FROM python:3.13-slim

RUN apt-get update \
  && apt-get install -y --no-install-recommends curl ca-certificates \
  && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY ai-service/ /app/

EXPOSE 9100
CMD ["python", "run.py"]
```

否则云端可能出现：

- 容器里找不到 `curl`
- HTTPS 证书校验失败
- 千问接口无法调用

## 8. 数据持久化和备份

第一阶段可以继续 SQLite，但必须做好持久化。

必须挂载：

```text
storage/inspectai.db
storage/uploads/
storage/logs/
```

建议每日备份：

```text
storage/inspectai.db
storage/uploads/
```

备份策略：

- 每天凌晨备份 SQLite 数据库
- 上传图片按日期或 recordId 归档
- 至少保留最近 7 天备份
- 重要演示前手动备份一次

第二阶段建议升级：

- SQLite → PostgreSQL / MySQL
- 本地 uploads → OSS / MinIO

## 9. 上云前必须补齐的功能

### 9.1 台账可编辑

用户最终要求台账能看数据，也能修改。

当前代码已能生成和查看台账，但尚未看到完整的资产编辑接口和页面。

建议补：

- `GET /api/assets/{id}`
- `PATCH /api/assets/{id}`
- 前端资产详情页
- 资产基础信息编辑表单
- 可编辑字段：资产名称、设备编号、位置、负责人、备注、处理进展
- 历史巡检记录只读

### 9.2 台账修改日志

正式版建议新增：

- `asset_change_logs`
- 记录修改人、修改时间、修改字段、修改前、修改后

第一阶段可以先不做复杂权限，但数据库结构最好预留。

### 9.3 提交校验

后端提交前必须校验：

- 必填字段不能为空
- 待人工复核字段不能直接提交
- 已提交记录重复提交不能重复累计台账次数

### 9.4 AI mock 风险控制

真 AI 模式下，不建议在千问调用失败时自动写入 mock 识别字段。

建议规则：

- `DEMO_MODE=true` 才允许 mock
- `DEMO_MODE=false` 且千问失败时，返回 `retake_required` 或 `manual_required`
- mock 数据不得沉淀进正式台账

### 9.5 鉴权

公网部署不能裸奔。

第一阶段至少：

- 简单访问密码或企业微信入口校验
- Nginx 限制后台调试接口

正式阶段：

- 企业微信 OAuth
- 绑定巡检员身份
- 记录编辑人和提交人

## 10. 迁移步骤建议

### 阶段一：云端演示版

目标：15 号前能稳定给领导演示。

步骤：

1. 准备云服务器和域名。
2. 安装 Docker 和 Docker Compose。
3. 上传 `inspectai/` 项目目录。
4. 新建 `.env.production`。
5. 修改 `docker-compose.yml` 使用 `env_file`。
6. 修改 `ai-service/Dockerfile` 安装 `curl` 和 `ca-certificates`。
7. 配置 Nginx HTTPS。
8. 启动服务：

```bash
docker compose up -d --build
```

9. 验证：

```text
GET https://你的域名/health
GET https://你的域名/
```

10. 企业微信后台配置可信域名和应用入口。

验收目标：

- 企业微信内能打开页面
- 入口默认拍照
- 能识别/手选模板
- 能进入字段确认
- 能提交日报
- 能生成台账

### 阶段二：正式试运行版

目标：能让小范围人员真实使用。

补齐：

- 企业微信 OAuth 登录
- 台账编辑和编辑日志
- PostgreSQL / MySQL
- OSS / MinIO 图片存储
- 自动备份
- 日志和监控
- 权限控制

## 12. 汇报口径

可以对领导这样说：

> 当前系统已经具备迁移到云服务器的基础，采用 Go 后端、Python AI 微服务和 Nginx 接入层的结构。第一阶段我们会按单机 Docker Compose 部署，先保证企业微信 HTTPS 入口、拍照识别、日报提交和资产台账沉淀能够稳定演示。后续正式试运行时，再升级数据库、对象存储、企业微信登录、台账编辑审计和自动备份。

一句话总结：

> 现在版本可以迁云做演示，但迁移前需要补部署配置、密钥管理、持久化挂载和台账编辑；正式生产再升级数据库、图片存储、鉴权和审计。
