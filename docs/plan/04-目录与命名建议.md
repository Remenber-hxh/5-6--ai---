## 命名规范（项目内部）

后续新增文件按这个规范走：

- 文件夹：全小写、英文、单词间用 `-`，例：`ai-service` / `go-backend` / `forms-export`
- 代码文件：按各语言惯例（Go: snake_case.go / Python: snake_case.py / JS: kebab-case.js）
- 文档：中英文都行，但**不带时间戳和长描述**，例：`方案总览.md` ✓ / `AI巡检填报助手_最终工程逻辑设计.md` ✗
- 案例素材：英文目录 + 数字编号，例：`cases/ups/01.jpg` / `cases/ups/02.jpg`

## 关于 InspectAI-Assistant 和 inspectai 的关系

我的判断（你可以否决）：
- `inspectai/` 是新版，codex 正在重写到这里。预计今天能跑起来。
- `InspectAI-Assistant/` 是 codex 半小时前的初版，已部署运行（端口 8080），可作为 fallback。
- 两边代码不会自动同步，**新功能（千问接入、3 次重拍、台账、移动端）只在 `inspectai/` 上做**，旧目录冻结。
- 等 `inspectai/` 验收通过后，旧的搬到 `archive/InspectAI-Assistant/` 留底，根目录就只剩短名了。
