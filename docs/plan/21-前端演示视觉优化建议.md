# 前端演示视觉优化建议

> 日期：2026-05-14  
> 适用项目：智巡 / InspectAI Assistant  
> 目的：在不推翻现有企业微信式移动端流程的前提下，提高领导演示时的视觉质感、产品完整度和“AI 巡检系统”的识别度。

## 1. 当前判断

当前前端已经具备完整操作链路：

```text
拍照 / 上传 → AI 识别 → 字段确认 → 日报预览 → 提交 → 资产台账 → 修改申请 → 主管审批
```

现在的问题不是“不能用”，而是“看起来还偏工具 Demo”。  
当前视觉风格接近 Material / 企业微信工具页，优点是清楚、轻量、移动端可操作；不足是第一屏记忆点弱，AI 识别过程不够可视化，台账页和资产详情页的管理感不够强。

领导演示场景下，前端要承担两个目标：

1. 让人一眼看懂：这是一个 AI 巡检系统，不是普通表单页面。
2. 让人相信：巡检数据不是填完就结束，而是会进入台账、可追溯、可审批。

## 2. 视觉方向

建议采用“工业科技 + 企业微信操作感”的折中方案。

不要把页面做成纯炫技大屏，也不要保持现在完全朴素的表单风格。移动端仍然要像企业微信里能直接用的工具，但第一屏、识别中、台账页、资产详情页需要有明显的产品包装。

建议视觉关键词：

```text
工业蓝绿、深色相机取景、扫描动效、白色管理卡片、状态色清晰、少量玻璃感
```

建议主色：

| 用途 | 建议 |
| --- | --- |
| 主色 | 深海蓝 / 工业蓝 |
| AI 强调色 | 青绿色 |
| 正常状态 | 安全绿 |
| 风险状态 | 预警橙 / 异常红 |
| 页面背景 | 浅灰白为主，第一屏可用深色渐变 |

## 3. 第一优先级：三页必须先美化

如果时间有限，先改这三处，投入最小，演示提升最大。

### 3.1 第一屏：智巡相机工作台

当前第一屏是深色背景 + 拍照按钮，能用但不够像产品。  
建议把第一屏改成“AI 取景工作台”。

建议元素：

- 顶部增加 `JADEAST · 智巡` 品牌识别。
- 中间增加取景扫描框，四角线条模拟设备识别框。
- 加一条轻微上下移动的扫描线，表示 AI 正在等待识别。
- 保留拍照按钮，但按钮可做成更强的主操作。
- 底部仍保留“从相册上传 / 手动选择模板”，避免影响现有流程。

建议文案：

```text
主标题：对准设备，AI 自动识别巡检字段
副标题：支持仪表读数、设备状态、异常风险与日报模板匹配
```

目标效果：领导打开页面第一眼就知道这是“智能巡检拍照入口”，不是普通上传页。

### 3.2 AI 识别中：把黑盒变成过程

当前识别中页面主要是 spinner，信息量偏低。  
建议把 AI 识别过程做成三步可视化。

建议展示：

```text
1. 正在识别巡检场景
2. 正在提取设备状态 / 表计读数
3. 正在匹配日报模板
```

可加轻量标签：

```text
设备状态
仪表读数
异常风险
日报模板
```

如果有上传图片，可以展示一张小缩略图，并在缩略图上叠加扫描线。  
这样 AI 不再像“等待加载”，而是像“正在分析现场图像”。

### 3.3 台账页：增加总览卡片

当前台账页是资产列表，适合使用，但不够体现管理价值。  
建议在资产列表上方加一个“台账总览”区域。

建议展示：

```text
资产总数
正常资产
异常 / 待复核
今日新增巡检
```

列表本身保留现有结构，但资产行可以更像“资产卡片”：

- 左侧保留设备图片缩略图。
- 中间显示资产名、项目、最近巡检人。
- 右侧显示状态徽标和累计巡检次数。
- 摘要最多两行，避免列表过长。

目标效果：让领导看到“日报不是孤立记录，而是在沉淀资产状态”。

## 4. 第二优先级：资产详情和审批页

### 4.1 资产详情页改成“资产档案页”

当前资产详情页偏表格式。建议改成更有管理系统感的“档案页”。

建议结构：

```text
顶部：资产状态卡
中部：最近总结
下部：巡检时间线
底部：修改申请入口
```

资产状态卡建议展示：

- 资产名称
- 当前状态
- 累计巡检次数
- 最近巡检时间
- 最近巡检人

巡检历史建议做成时间线，不要只是普通折叠列表：

```text
2026-05-13 16:16
  已提交 · 3 张照片 · AI识别
  关键字段摘要

2026-05-12 15:30
  人工填写 · 1 张照片
  关键字段摘要
```

### 4.2 审批页突出“留痕”和“可控”

审批页不要做得太花，重点是让人感到数据修改是有流程的。

建议每条审批卡片展示：

- 申请人
- 修改对象
- 修改内容摘要
- 修改理由
- 审批意见
- 通过 / 驳回按钮

状态色建议保持克制：

| 状态 | 颜色 |
| --- | --- |
| 待审批 | 橙色 |
| 已通过 | 绿色 |
| 已驳回 | 红色 |
| 已撤回 | 灰色 |

## 5. 桌面演示模式建议

领导演示一般是电脑投屏，当前页面最大宽度 480px，像普通手机网页。  
建议桌面端增加“演示包装”，移动端仍保持原样。

桌面端建议：

- 页面背景用深色科技渐变或轻微网格。
- 中间显示手机框，里面跑现有移动端界面。
- 右侧增加三条价值说明：

```text
拍照即填报
人工确认留痕
自动沉淀台账
```

这样在投屏时，画面会像正式产品 Demo，而不是浏览器里打开了一个手机网页。

## 6. 动效建议

动效要少，但要有意义。

建议保留或新增：

- 第一屏扫描线缓慢移动。
- 页面切换时轻微上滑 / 淡入。
- 资产列表错位淡入。
- AI 识别中的步骤逐个高亮。
- 弹层从底部滑入。

不建议：

- 大量弹跳动画。
- 过多渐变和发光。
- 每个按钮都复杂动效。
- 页面里同时出现多个抢眼动画。

## 7. 文案建议

当前文案偏功能描述，可以稍微产品化，但不要太营销。

建议替换：

| 当前 | 建议 |
| --- | --- |
| 对准巡检设备拍照 | 对准设备，AI 自动识别巡检字段 |
| AI 会自动识别场景，调出对应的日报模板 | 支持设备状态、表计读数、异常风险与日报模板匹配 |
| 资产台账 | 资产台账 |
| 待审批申请 | 数据修改审批 |
| AI 总结（基于人工确认字段生成） | AI 总结（仅基于已确认字段） |

核心表述建议保持这三句话：

```text
拍照即填报
填报即台账
修改可审批
```

## 8. 不建议当前阶段做的事

当前不要大规模重构前端框架。  
原因是项目已经进入演示前阶段，功能链路比技术洁癖更重要。

暂不建议：

- 引入 Vue / React 重写。
- 新增复杂路由系统。
- 大规模改接口结构。
- 把所有页面都做成大屏风格。
- 为了视觉牺牲企业微信内的移动端可用性。

## 9. 推荐落地顺序

### 第一步：演示观感提升

优先改：

```text
第一屏
AI 识别中
台账总览
```

这三处最容易被领导看到，也最能体现产品价值。

### 第二步：管理闭环增强

继续改：

```text
资产详情页
审批页
修改申请弹层
```

重点体现“数据可追溯、修改有流程”。

### 第三步：桌面投屏包装

最后补：

```text
桌面手机壳
右侧价值说明
深色科技背景
```

这部分主要服务汇报演示，不影响移动端使用。

## 10. 给 Claude 的执行建议

建议 Claude 优先改 `frontend/styles.css` 和少量 `frontend/index.html`，尽量少动 `frontend/app.js`。

推荐文件范围：

| 文件 | 建议 |
| --- | --- |
| `frontend/styles.css` | 主要改视觉、动效、桌面演示包装 |
| `frontend/index.html` | 只在必要时增加少量静态结构，例如品牌、台账总览容器 |
| `frontend/app.js` | 只在需要渲染台账统计、识别步骤状态时少量修改 |

执行原则：

- 保持现有 8 个 scene 不变。
- 保持现有 API 不变。
- 保持移动端操作优先。
- 不破坏拍照、上传、人工填写、提交、台账、审批流程。
- 视觉升级后必须重新跑一遍完整演示链路。

## 11. 验收标准

视觉升级后，用下面标准判断是否合格：

```text
1. 打开首页 3 秒内能看懂：这是 AI 巡检拍照入口。
2. AI 识别中页面能让人感到“系统正在分析图片”，不是单纯等待。
3. 台账页能一眼看到资产状态总览。
4. 资产详情页能体现“历史沉淀”和“可追溯”。
5. 审批页能体现“修改有流程、有留痕”。
6. 手机端仍能正常拍照、上传、填写、提交。
7. 桌面投屏时页面不像普通网页，而像正式产品演示。
```

## 12. 一句话结论

当前前端功能已经能支撑演示，但视觉还停留在“可用工具”。  
下一步不要重做系统，应围绕第一屏、AI 识别中、台账总览和资产详情做包装，让它从“能跑的 Demo”升级为“领导能看懂、愿意继续投入的产品原型”。
