# 密钥加密方案

> 解决"key 不能明文落盘"的安全要求。
> 适用：本地演示阶段（单台 Windows 机器、单一 Windows 用户）。
> 不适用：生产部署（要切 KMS / Vault / Azure Key Vault，见底部"升级路径"）。

## 加密机制

**Windows DPAPI（Data Protection API）— CurrentUser scope**

DPAPI 是 Windows 内置的加密 API，密钥派生自 Windows 用户登录凭据。
- 加密的密文只有**同一 Windows 用户在同一台机器上**才能解密
- 不需要密码，不需要密钥管理服务
- 把 `.env.secure` 文件复制到别的电脑上无法解密
- 把 `.env.secure` 给同机的另一个 Windows 账号也无法解密

PowerShell 内置封装：`ConvertFrom-SecureString`（加密）+ `ConvertTo-SecureString`（解密），底层就是 DPAPI。

## 文件清单

| 文件 | 作用 | 是否加密 | git 状态 |
| --- | --- | --- | --- |
| `inspectai/.env` | 非敏感配置（provider、model name 等） | 明文 | gitignored |
| `inspectai/.env.secure` | 加密的密钥列表（DASHSCOPE_API_KEY 等） | DPAPI 密文 | gitignored |
| `inspectai/.env.example` | 配置模板 | 明文（无真实 key） | 入库 |
| `inspectai/scripts/setup-key.ps1` | 设置 / 删除加密密钥 | — | 入库 |
| `inspectai/scripts/start-local.ps1` | 启动时自动解密注入 env | — | 入库 |

## 操作

### 设置 / 更换 key

交互输入（推荐，输入不回显，不进 PowerShell 历史）：
```powershell
cd "D:\5-6月 ai 大会\inspectai"
.\scripts\setup-key.ps1
# 提示后粘贴 key，回车
```

命令行传入（不推荐，会进 `(Get-History)`）：
```powershell
.\scripts\setup-key.ps1 -Key "sk-xxxxxxxxxxxxxx"
```

设置其他 key（比如未来要加 OpenAI）：
```powershell
.\scripts\setup-key.ps1 -Name "OPENAI_API_KEY"
```

### 删除 key

```powershell
.\scripts\setup-key.ps1 -Remove
.\scripts\setup-key.ps1 -Name "OPENAI_API_KEY" -Remove
```

### 查看是否已设置

```powershell
Get-Content -LiteralPath "D:\5-6月 ai 大会\inspectai\.env.secure"
```
看到的是 `KEY=01000000d08c9ddf...`（DPAPI 密文头），不是明文。

### 启动服务（自动解密）

```powershell
.\scripts\start-local.ps1
```

启动脚本会按顺序：
1. 加载 `.env`（明文配置）
2. 加载 `.env.secure`（解密 key 注入到进程环境变量）
3. 启动 `python run.py` 和 `server.exe`，子进程继承父进程环境变量

如果 `.env.secure` 不存在 / 解密失败，脚本会跳过（带警告），AI service 会回退 mock 模式。

## 安全边界

### 防什么

- ✅ 防止 git 误提交泄露：`.env.secure` 已 gitignore
- ✅ 防止文件直接外发泄露：密文复制到别的机器无法解密
- ✅ 防止 PowerShell 历史泄露：`setup-key.ps1` 默认交互式输入不回显
- ✅ 防止同机其他 Windows 账号偷读：DPAPI CurrentUser scope + NTFS ACL 仅当前用户可读

### 防不了什么

- ❌ 当前 Windows 用户**已登录**时，任何能在该用户上下文运行进程的程序都能解密（恶意软件、远程桌面入侵后）
- ❌ Windows 用户密码被破解后，密文可被解密
- ❌ 已注入到进程环境变量的 key 在内存里是明文（任何能 attach 该进程的工具都能读，比如 `Process Explorer` 提权后看 `Strings`）
- ❌ 网络传输时是明文 HTTPS body（这是 dashscope SDK 协议决定的，无法改）
- ❌ AI 服务的 stdout/stderr 如果 echo 了 key 就会写到日志（已检查 `run.py` 不会 echo key）

### 风险评估（演示场景）

对一个**本地演示项目**：DPAPI 已经是 PowerShell 原生能给出的最佳方案，无需额外引入 KeePass / Vault 等工具。
对一个**生产部署**：必须升级到 KMS / Vault（见下方）。

## 升级路径（生产部署时切换）

| 阶段 | 方案 | 触发条件 |
| --- | --- | --- |
| 本地演示 | DPAPI（当前） | 单机单用户 |
| 内网 / 多机 | HashiCorp Vault / Azure Key Vault | 多用户访问、需要审计 |
| 公有云 | AWS KMS / 阿里云 KMS | 上云、需要 IAM 权限隔离 |
| Kubernetes | Sealed Secrets / External Secrets Operator | K8s 部署 |

切换时只需替换 `start-local.ps1` 里 `Load-DotEnvSecure` 的实现，业务代码（`run.py` 读 `os.environ.get(...)`）完全不变。

## 不做的事

- ❌ 不引入 PyCryptodome / cryptography 等三方加密库（DPAPI 够用，少依赖）
- ❌ 不做 master password（用户体验差，且 master password 自己也要保存）
- ❌ 不做密钥轮换自动化（演示阶段一次设置即可）
- ❌ 不做 HSM（硬件安全模块，演示场景成本不值）
