# 移动端(mobile-web)浅色页精修 — 改动与建议(2026-07-30)

## 背景与方向

体检发现 mobile-web 是「双主题」:登录/拍照/识别中/个人页是深色科技风,
台账/任务/审批/填报等流程页是浅色 iOS 风(沿用旧版设计)。问题不在双主题本身,
而在浅色页做得太糙:通用 iOS 蓝与品牌翡翠色完全脱节、卡片贴边、空态只有一行灰字,
看起来像个没做完的默认模板。

经确认方向:**保留双主题,精修浅色页**(浅色底在户外阳光下对巡检员更可读)。
对比截图在 `mobile-web/shots_before/` 与 `mobile-web/shots_after/`。

## 改了什么

### 1. 强调色品牌化(最大杠杆)

浅色页强调色从通用 iOS 蓝 `#007aff` 换成深翡翠 `#0a8a63`
(即深色页 `--tech-jade` 的浅色 grade,与白底/白字对比均 ≥ 4.3:1)。

- `global.css` 令牌:`--ios-blue` → `--brand`,`--c-blue-soft` → `--brand-soft`,
  新增 `--brand-border`;8 处硬编码 `rgba(0,122,255,*)` 全部归到翡翠色系。
- 按钮、选中态、chip、AI 药丸、进度条等 30+ 处自动生效。
- 语义色不动:成功绿 `--ios-green` / 警示橙 `--ios-orange` / 红 `#ff3b30`。

### 2. 卡片系统

- 新增 `--lt-shadow` 令牌(带绿底灰的统一软阴影),12 处各写各的 box-shadow 收敛到一处。
- 修复**贴边卡片**:`.lo-row` / `.lg-card` / `.asset-list` / `.ad-card` / `.pv-card` /
  `.cr-card` / `.ad-history` 原来没有水平外边距,白卡直接顶到屏幕边缘;
  统一为 16px 外边距 + 16px 圆角。
- 台账概览卡加按下缩放反馈,数字字重/字距收紧。

### 3. 新组件

- `.empty-state`(整屏空态:徽章 + 标题 + 提示),替掉原来飘在屏中间的一行灰字。
  已用于:审批清零、任务清零、台账筛选无结果。
  局部小块空态(如资产详情的历史记录)仍用 `.task-empty`,别混。
- `.btn-dark-ghost`(深色屏描边按钮)。

### 4. Bug 修复

- **`--foreground` 未定义**(`global.css` `.app-navbar-dark`):旧版令牌名残留,
  之前靠继承侥幸没翻车,已改 `--ink` 并留注释。
- **台账假日期**:Go 零值时间(`0001-01-01`)让未巡检设备行尾挂着「12/31」,
  `LedgerPage.fmtDate` 加年份 < 2000 防御。
- **文案自相矛盾**:台账第一张卡「已巡设备 34」与列表里的未巡检行矛盾,改「设备总数」。
- **混主题按钮**:审批页「没有审批权限」、资产详情「设备不存在」两个深色屏
  错用浅色页的 `.task-back`,已换 `.btn-dark-ghost`。

## 验证

- `npm run typecheck` ✅,`npm run build` ✅
- Playwright 实机截图复核:台账(含筛选选中态)/ 任务 / 审批空态 / 资产详情 / 选照片页,
  见 `shots_after/`。

## 备注(给后来的人)

- **不要再把 iOS 蓝加回来。** 浅色页强调色唯一来源是 `--brand` 系列;
  新页面先吃令牌,不要在组件里散写颜色(本项目注释文化:数值出处写清楚)。
- 深色页 = 登录/拍照/识别中/个人页;浅色页 = 其余。新页面入局前先选边,
  深色屏上的按钮用 `.btn-dark-ghost`,别拿浅色页的按钮凑。
- `.retake-box` 只有浅色一份是有意为之(见 CSS 注释,历史上深色双份覆盖踩过对比度的坑)。

## 建议(本次没做,按优先级)

1. **走一遍完整填报流程目检**。选照片页已验证;classify/record/preview 需要真实
   巡检数据才能进,本次只过了令牌层面的回归,建议真机走一遍拍照→识别→填报→提交。
2. **个人页(/me)太单薄**:只有姓名 + 退出。管理角色落在这里,至少该给
   台账/任务/审批的快捷入口,或版本号、账号信息。
3. **后端种子数据清洗**:台账里 FT-2 这类「状态=正常 但 巡检 0 次、无巡检时间」
   的自相矛盾数据是后端种出来的,显示层已兜底,建议从源头洗。
4. **global.css 已 1800+ 行**,单文件继续长会难维护。建议按 section 拆成
   tokens / dark / flow / pages 几个文件,或在文件内严守现有注释分区。
5. 双主题跳转(深色拍照 → 浅色填报)仍有轻微割裂感。若将来想统一深色,
   令牌层已备好(`--brand` 就是浅色 grade 的翡翠),翻令牌即可,不用改组件。

## 首页(拍照台)重排 — 同日追加

旧首页的毛病:取景框只是个装饰性空框(占着黄金位置不干事);导航是
「文字链接 + 圆点分隔符」,五个入口换行堆成两行,像页脚不像入口;
身份信息顶栏和快门下重复出现两次。

### 新结构(自上而下)

1. **顶栏**:品牌徽章 | 在线状态 + 用户入口(不动)。
2. **眉行** `部门 · 角色`(11px 加宽字距)+ 大标题 + 动态副标题(在线/离线文案)。
3. **取景框即快门**:整个框都是点按区(`.vf-btn` 包 `capture` 文件输入),
   框内中央保留白色快门环作视觉锚点。弱网/手套/颠簸现场不用瞄准小圆钮。
4. **从相册上传**:独立描边胶囊(`.cap-album`),与拍照是并列的两种录入方式。
5. **工作台磁贴**(`.cap-nav`):我的任务 / 设备健康 / 待审批 / 待处理照片,
   细线 SVG 图标(手写,不引图标库)+ 红色待办角标,等宽一排。
6. **待上传面板** PendingPanel(不动):只显示本机待传队列;
   注意它和「待处理照片」角标口径不同 —— 角标含已上传待识别的,面板只装本地队列。

### 清理

- 删除死样式:`.shutter-*`、`.capture-who`、`.hero-secondary`、`.link-btn`、`.link-sep`。
- `.capture-main` 从「整屏硬挤压」改为可内部滚动,iPhone SE(375×667)实测不溢出。
- 验证:typecheck ✅;375×812 与 375×667 两种机位截图(`shots_after/home_new*.png`)。

### 后续可做

- 取景框未来可接 `getUserMedia` 实时预览(现在是无预览的离线优先设计);
  要做的话注意 HTTPS/权限弹窗与耗电。
- 工作台磁贴可按角色定制(巡检员不看审批,或许更想看到「我的日报」入口)。
