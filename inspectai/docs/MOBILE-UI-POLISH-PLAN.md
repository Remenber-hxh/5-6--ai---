# 移动端 UI 美化方案

> 状态:**待评审**(2026-08-02)。一行未执行。
> 范围:`mobile-web` 浅色页为主。深色拍照台已在旧版基础上回归,本轮不动。

## 立场

已经定下来的三条,本方案在此基础上做,不再重开:

- **双主题保留**:拍照台深(取景语境),数据页浅(户外强光下可读性更好)
- **浅色页用企业微信配色**(官方色值),理由是环境一致 —— 用户一整天在企微里
- **次文字有意偏离官方**:`#666666` 而非 `#999999`,官方值在白卡上只有 2.85:1,
  而这一层承载设备位置、巡检次数、时间,户外要读

所以下面**不谈换配色**,只谈配色之外的事 —— 那些才是现在观感的短板。

---

## 一、优先做:三条实测看到的问题

### 1. 台账筛选区吃掉大半屏 ⭐ 收益最大

**实测**:设备类型 11 个 chip 排 4 行,加上项目分组,真正的设备列表被挤到
第一屏之外 —— 打开台账看到的全是筛选器。

**为什么是问题**:筛选器是工具,不是内容。管理者打开台账是想看设备状态,
不是想看有哪些筛选项。现在信息优先级完全倒过来了。

**做法**:整个筛选区收进一个 `Collapse`,默认收起,标题行显示当前筛选状态
(如「全部设备」/「会议中心 · 电梯」)。已选中的 chip 在收起状态下作为
摘要显示,不用展开也知道自己筛了什么。

**代价**:多一次点击才能改筛选条件。但改筛选是低频动作,看列表是高频动作 ——
应该优化高频那个。

### 2. 未巡检设备的封面是空灰框

**实测**:34 台设备里大部分没巡检过,封面位是一列空的圆角灰块,一眼看过去
像整页图片加载失败。

**做法**:按设备类型给线性图标占位(电梯 / 水泵 / 配电柜…),`components/icons.tsx`
已有这套手写图标的模式,扩几个即可。图标用 `--lt-fg-3` 淡灰,不抢内容。

**代价**:要为每种设备类型画图标。当前有 11 种类型,可以先做前 5 种覆盖 80%
的设备,其余落到一个通用「设备」图标。

### 3. 卡片套卡片,三层视觉层级

**实测**:灰底页面 → 白色分组卡 → 卡里再放 chip 胶囊。iOS 设置页只有两层。

**做法**:分组卡去掉外层白卡,直接用「灰底 + 发丝分割线」分隔,和企微列表
一致。这一条和已经做过的「压扁阴影」是同一个方向 —— 少一层视觉层级。

## 二、值得做:补上"完成感"

### 4. 提交日报后没有收束

**现状**:提交完直接跳回,没有任何"这件事完成了"的反馈。巡检员做完一单
最需要的就是这个确认。

**做法**:成功页 —— 大对勾 + 「日报已提交」+ 本次概要(设备名、字段数、
耗时)+ 「继续巡检」主按钮。停留 1.5 秒或点按钮返回。

> 更正:这里原先写「Arco `Result`」。**库里没有 Result 组件**(2026-08-03
> 逐个目录核对过 56 个组件)。这页得自己写,或用 `Dialog` + 自定义内容。
> 工作量因此从"小"上调为"中"。

**为什么值得**:这是全流程唯一的正反馈时刻。做巡检是重复枯燥的工作,
一个明确的"完成"比任何配色都更影响使用感受。

### 5. 待处理照片的批量操作太重

**现状**:要先点「选择」进入多选模式,再勾选,再点删除 —— 三步。

**做法**:`SwipeAction` 左滑单条直接删。多选模式保留给"删一批"的场景。

## 三、我不建议做的

| | 为什么 |
|---|---|
| 加载动画 / 粒子 / 渐变光效 | 用户戴手套、在机房、赶时间,炫技只会拖慢他们 |
| 全站统一成深色 | 牺牲户外可读性,拿真实使用场景换观感 |
| 引图标库 | 全站只用到 ~10 个图标,手写细线 SVG 已够,风格也更可控 |
| 骨架屏加扫光动画 | 已用呼吸(breath),扫光在铺满卡片时很吵 |

「呼吸感」这个方向本身是对的,但要落在**状态反馈**上(保存中、上传中、
识别中已经做了),不是落在装饰上。

## 四、建议顺序

| 序 | 事项 | 工作量 | 收益 |
|---|---|---|---|
| 1 | 台账筛选收起 | 小 | 大 —— 管理者最常看的页 |
| 2 | 设备类型图标占位 | 中 | 中 |
| 3 | 提交成功页 | 中 | 大 —— 唯一的正反馈时刻 |
| 4 | 卡片层级压扁 | 中 | 中 |
| 5 | 左滑删除 | 小 | 小 |

1 和 3 各自半天内能看到效果,建议先做这两个。

## 四之二、组件库还剩什么可用(2026-08-03 盘点)

库里 56 个组件,已接进 `src/ui/` 适配层的 18 个。**没接的不等于该接** ——
下面是逐个看过之后的结论,免得下次再从头过一遍。

### 值得接(按顺序)

| 组件 | 用在哪 | 换掉的是什么 |
|---|---|---|
| `Collapse` | 台账筛选区 | 手写展开逻辑,见上文第 1 条 |
| `SwipeAction` | 待上传照片 | 三步删除,见上文第 5 条 |
| `DatePicker` | 「检查时间」等日期字段 | 现在是纯文本输入,格式全靠人自觉 |
| `Sticky` | 台账/设备健康的分组标题 | 长列表滚起来不知道当前在哪一组 |

### 看过之后不接的

| 组件 | 为什么不接 |
|---|---|
| `Tag` | 只有展示态,**没有选中态**。台账的 `.lg-chip` 要的是"可点选 + 带计数",接了还得自己补状态;而只读的状态胶囊(`.sum-status` / `.ctx-badge`)已按旧版逐像素对过,换过去等于把对齐好的又推翻 |
| `Ellipsis` | 折长文用。实测真实数据:AI 总结中位 **144 字**(最长 179),建议单条中位 48 字 —— 才五六行,折起来省不了多少,却多一次点击,而这段正是要读的 |
| `Divider` | 一条线,CSS 一行的事 |
| `Form` | 字段页已有自己的保存/校验/置信度逻辑,换过去是重写不是复用 |
| `Grid` | 首页入口已定稿,不为用组件而改版 |
| `Search-bar` | 台账目前靠维度筛选,设备量级还没到要搜的程度 |
| `Steps` | 流程进度已由 `FlowHeader` 顶部细进度条承担,再加一排步点是重复 |
| `Carousel` `Rate` `Slider` `IndexBar` `Keyboard` `CountDown` `Stepper` `Switch` `Notify` `Pagination` `ActionSheet` 等 | 现有页面里没有对应场景,为用而用 |

**要留意的两条**:

- 库里**没有 `Result`**。成功页得自己写(见上文更正)。
- Arco 的内部类名**不带 `arco-` 前缀**(`.cell-title` / `.radio-icon` /
  `.preview-image-wrap`)。写覆盖样式前先去 `node_modules/.../style/css/index.css`
  查真名,别照 `arco-` 猜 —— 之前在分段控件和角标上各栽过一次。

## 五、还没解决、但比美化更要紧的

写在这里免得被观感问题盖过去 —— 详见 `project-mobile-web-gaps` 记忆:

- **巡检员发不了数据修改申请**,审批闭环只搭了一半,主管的待审批页永远是空的
- **会话不校验**,改了角色/停用账号后客户端仍按旧身份路由
- **部署层为零**,`mobile-web` 没有 Dockerfile / compose 挂载 / nginx location

美化到什么程度都不影响这三条 —— 它们是功能缺口,不是观感问题。
