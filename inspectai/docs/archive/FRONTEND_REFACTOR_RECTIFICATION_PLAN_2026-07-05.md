# 智巡前端整改与重构交接方案

更新时间：2026-07-05  
适用范围：智巡移动端、管理后台、Agent 首页与可视化页面  
目标读者：Claude / 前端研发 / 项目汇报准备人员

## 1. 整改背景

当前项目已经跑通了核心业务链路：移动端拍照识别、字段确认、日报提交、资产台账、审批、巡检计划、数据看板、Agent 问答和企业微信通知。但前端仍以原型式迭代为主，存在三个问题：

- 视觉风格不够统一：移动端、管理后台、登录页、Agent 首页、数据看板存在不同阶段的样式痕迹。
- 页面信息偏冗余：部分页面文字说明过多，用户需要扫很多字才能理解当前要做什么。
- 交互闭环不够直观：计划、审批、台账、异常、Agent 跳转之间虽然已有功能，但用户感知上还没有形成“从问题到处理”的清晰路径。

这次整改不是简单换皮，而是把前端整理成一个更适合比赛展示和后续生产迭代的界面体系。

## 2. 整改总目标

前端整改应围绕三个关键词展开：

- 直观：进入系统后，用户能立刻知道当前重点、待处理事项和下一步操作。
- 高级：视觉风格统一，减少白底表格堆叠，保留科技感但不牺牲可读性。
- 可维护：从原来的零散 HTML / JS / CSS 逐步过渡到工程化前端，方便后续扩展组件、路由、权限和状态管理。

## 3. 推荐技术路线

### 3.1 管理后台

推荐采用：

- Vue 3
- Vite
- TypeScript
- Naive UI
- Pinia
- Vue Router
- ECharts

理由：

- Vue 3 学习成本和迁移成本比 React 更低，适合当前项目快速重构。
- Naive UI 适合管理后台，组件完整，表格、弹窗、表单、菜单、标签、通知等生产组件齐全。
- ECharts 继续用于数据看板、趋势分析、资产健康统计。
- TypeScript 用于约束接口数据结构，减少后续页面越改越乱。

### 3.2 移动端

推荐采用：

- Vue 3
- Vite
- TypeScript
- Vant

理由：

- 移动端主要面向企业微信内嵌访问，Vant 更适合表单、弹窗、按钮、上传、步骤条、Toast 等移动操作。
- 移动端不要做复杂炫技动效，优先保证拍照、上传、字段确认、补图、提交顺畅。

### 3.3 动效方案

推荐分层使用：

- CSS：用于发光边框、扫描线、按钮反馈、卡片 hover、状态闪烁。
- Anime.js：用于首页 Agent、数据卡片、流程节点的轻量动效。
- Lottie：用于 AI 识别中、Agent 思考中、通知成功等固定动画。
- Rive：后期用于 Agent 形象，不作为当前必须项。

不建议当前直接使用 GSAP 做全站重动画，也不建议先上复杂 3D。当前重点是稳定、清晰、可交付。

## 4. 页面整改方向

### 4.1 登录页

保留当前科技城市巡检风背景，登录卡片继续使用深色半透明玻璃质感。

整改要求：

- 背景图统一使用一张高质量科技城市/园区巡检图。
- 登录卡片只保留必要字段：系统名、账号、密码、登录按钮。
- 密码框保留小眼睛显示/隐藏功能。
- 边框使用动态微光，但发光只体现在边框，不影响卡片主体颜色。
- 删除说明性废话，不放“介绍 1/2/3”一类内容。

### 4.2 管理后台首页

首页应从“信息展示页”转为“Agent 工作台”。

整改要求：

- 删除“巡检管理 · 快速入口”式普通入口区。
- 删除不必要的“AI 本月成绩”等展示型模块。
- 首页主视觉保留一个可收起的 Agent 窗口。
- Agent 应支持自然语言提问，并给出可点击动作，例如：
  - 查看今日异常资产
  - 打开审批中心
  - 跳转巡检记录
  - 查看某台设备台账
  - 生成日报/周报
  - 分析本周高风险资产
- Agent 回复不要大段废话，应采用“结论 + 操作按钮 + 数据来源”的结构。

推荐首页结构：

- 顶部：项目选择、刷新、待审批、用户信息。
- 主区域：Agent 窗口。
- 右侧或下方：少量关键状态卡片，例如待审批、异常资产、今日巡检、需补图。
- Agent 折叠后，保留一个悬浮入口。

### 4.3 资产台账

资产台账是管理后台的核心页面，不应只是表格。

整改要求：

- 保留资产列表、筛选、导出、详情抽屉。
- 强化资产详情：基础信息、巡检轨迹、近 30 天状态、AI 摘要、关联照片、异常记录。
- 资产详情要能解释“这台设备现在是否健康、最近有没有反复问题、下一步该关注什么”。
- 导出必须是标准表格文件，不要假导出或非结构化文本。

### 4.4 巡检记录

巡检记录要承担“过程追溯”的作用。

整改要求：

- 状态字段统一为：正常 / 异常 / 待复核 / 需补图 / 人工填写 / 已完成。
- 不要把“已识别、已提交”当业务状态。
- 每条记录要能看到：照片、AI 识别字段、人工修正字段、AI 总结、风险建议、处理状态。
- 编号规则要可读，例如：`REC-20260616-会议中心-有机房电梯-001`。

### 4.5 审批中心

审批中心应承接“异常复核”和“修改申请”，减少独立模块数量。

整改要求：

- 异常复核并入审批中心。
- 审批类型包括：补图申请、字段修改、异常确认、人工兜底。
- 审批通过后，前端状态必须同步变化，不能出现审批通过但记录仍显示异常的问题。
- 审批详情要展示原始照片、原字段、修改字段、申请理由、处理结果。

### 4.6 巡检计划

巡检计划应体现计划到执行的闭环，不要和任务割裂。

整改要求：

- 任务合并到计划中，不再单独做一套“巡检任务”入口。
- 新建计划后先进入“待执行”，不应立刻下发移动端。
- 管理员点击“执行/下发”后，状态变为“进行中”，再下发给移动端。
- 移动端完成后，计划关联任务进入“已完成”。
- 顶部状态卡片建议保留：待执行 / 进行中 / 需跟进 / 已完成。
- 点击状态卡片弹出对应列表，点击单个任务查看详情。

### 4.7 数据看板

数据看板要减少装饰性内容，突出管理判断。

整改要求：

- 删除过多二级说明小字。
- 近期重点关注放在资产状态或趋势区域下方。
- 趋势分析页突出：异常趋势、重点资产、巡检质量、字段漂移。
- 红色不要滥用，只用于真正异常或高风险。
- 图表要配合 AI 结论，不要只展示好看的图。

### 4.8 提示词模板中心

提示词模板中心是后续 AI 可维护的关键。

整改要求：

- 后台用表单方式管理提示词模块，而不是让用户编辑一大段 Prompt。
- 先以“有机房电梯”为标准模板。
- 模块建议包括：
  - 场景识别
  - 必拍照片要求
  - 字段提取
  - 判断规则
  - 感知类字段
  - 输出格式
  - 风险总结
  - 低风险总结
- 支持预览渲染后的完整 Prompt。
- 支持版本号、启用状态、更新时间、修改人。

## 5. 视觉整改原则

### 5.1 总体风格

推荐方向：深色科技感 + 白色业务内容区 + 克制动效。

具体原则：

- 管理后台主体仍以白色内容区为主，保证表格、字段和审批可读。
- 侧边栏、首页、登录页可保持深色科技风。
- 主色建议使用青绿/蓝绿，不要混入过多紫色、红色和渐变。
- 所有卡片圆角、阴影、间距统一。
- 所有按钮分层明确：主按钮、次按钮、危险按钮、文本按钮。

### 5.2 文案原则

用户明确要求减少文字，因此前端文案应遵守：

- 标题短。
- 说明少。
- 能用状态和数据表达的，不写长说明。
- Agent 回复不超过三段。
- 每个页面最多保留一条必要说明。

### 5.3 交互动效原则

动效只服务三个场景：

- 告诉用户正在识别/分析。
- 告诉用户当前状态变化。
- 引导用户点击下一步。

不要为了炫技添加无意义动画。

## 6. 分阶段实施方案

### 第一阶段：不破坏现有功能的 UI 整理

目标：短期可演示。

工作项：

- 统一后台间距、卡片、按钮、标题层级。
- 删除冗余说明文字。
- 优化首页 Agent 区域。
- 优化数据看板、巡检计划、资产台账页面布局。
- 保持现有接口不变。

验收标准：

- 现有功能不丢。
- 页面不再出现明显错位和多余说明。
- 演示能从 Agent 首页串联到审批、台账、巡检记录、数据看板。

### 第二阶段：管理后台工程化重构

目标：建立长期可维护前端框架。

工作项：

- 新建 `admin-web/`，使用 Vue 3 + Vite + TypeScript + Naive UI。
- 先重构管理后台基础框架：登录、布局、路由、权限、API 封装。
- 页面按优先级迁移：Agent 首页、资产台账、巡检记录、审批中心、巡检计划、数据看板、提示词模板。
- 旧版 `admin-frontend/` 暂时保留，避免一次性切换风险。

验收标准：

- 构建产物可接入现有 Nginx。
- 页面能调用现有 Go 后端接口。
- 权限、登录、刷新、跳转、导出可用。

### 第三阶段：移动端工程化重构

目标：保证一线巡检员流程稳定。

工作项：

- 新建 `mobile-web/`，使用 Vue 3 + Vite + TypeScript + Vant。
- 重构移动端流程：登录/身份、首页拍照、模板选择、AI 识别、字段确认、补图、提交、我的任务。
- 优先保证企业微信内嵌访问体验。

验收标准：

- 快门按钮、相册上传、手动模板选择全部可用。
- 补图流程可回到对应记录。
- 移动端完成任务后，管理后台状态同步。

## 7. 交接给 Claude 的执行边界

Claude 执行时需要注意：

- 不要一次性重写全部前端。
- 不要删除现有可用入口。
- 不要随便新增临时端口。
- 不要把演示假数据写死到业务代码里。
- 不要增加大量说明文字。
- 不要为了美观破坏业务状态流转。
- 新 UI 必须能解释系统作用：拍照识别、字段确认、异常复核、资产沉淀、趋势分析、企业微信通知。

## 8. 验收清单

前端整改完成后，至少按以下清单验收：

- 登录页样式完整，密码小眼睛可用。
- 管理后台首页以 Agent 为核心，不再是普通快捷入口堆叠。
- Agent 可跳转到审批、资产台账、巡检记录、数据看板、巡检计划。
- 资产台账筛选、详情、导出可用。
- 巡检记录状态规范，不出现“已识别、已提交”作为业务状态。
- 审批中心能处理补图、修改、异常确认。
- 巡检计划能从待执行到进行中再到已完成。
- 数据看板无冗余二级说明文字。
- 移动端拍照识别按钮可用，布局无横向滚动条。
- 所有页面视觉风格统一，按钮、卡片、标题、状态标签一致。

## 9. 最终汇报口径

前端重构不是为了“换好看一点”，而是为了让系统从一个功能原型变成可交付产品：

- 一线员工看到的是清晰的移动作业入口。
- 管理人员看到的是资产状态、异常闭环和趋势判断。
- AI 不只是识别图片，而是作为 Agent 串联台账、审批、计划和报告。
- 数据不只是一次性日报，而是长期沉淀为设备资产档案。
