# 国会真实工程计划闭环修正版方案

日期：2026-06-05  
依据文件：`国会2026年工程计划事项.xlsx`  
适用系统：JADEAST 智巡后台 / 移动端 / AI 管理分析

---

## 1. 真实计划表带来的关键修正

之前的方案偏向“巡检计划 -> 巡检任务 -> 移动端拍照 -> 台账闭环”，适合日常巡检场景。

结合这份真实 Excel 后，需要修正为：

> 系统不只是做日常巡检计划，而是要承接“年度工程计划事项”的执行闭环。

真实业务里包含三类对象：

- 年度工程计划事项：强制检测、重点外委、零星工程、自行维保、CAPEX/FFE。
- 现场执行任务：检测、维保、维修、合同执行、资料上传、复核验收。
- 结果沉淀台账：资产台账、证照报告台账、合同台账、费用台账、异常整改台账。

所以系统模块命名和设计建议从：

```text
巡检计划 / 巡检任务
```

升级为：

```text
工程计划 / 执行任务 / 巡检记录 / 资产台账 / 证照报告台账
```

如果暂时不改菜单名称，也要在内部数据模型上按“工程计划事项”设计，不能只按日常巡检设计。

- 责任人分派。
- 合同或第三方外委闭环。

## 3. 业务分类修正

真实业务不能只按“巡检计划”分类，建议分成 5 类。

### 3.1 强制检测

代表事项：

- 建筑消防设施检验报告。
- 水质检测报告。
- 军团菌检测。
- 电梯安全年度检验报告。
- 绝缘工器具检验报告。
- 防雷装置定期检查报告。
- 消防电气防火检测报告。
- 压力容器定期检测报告。
- 仪表维保及检测。
- 可燃气体探测器检测。

闭环重点：

- 是否按期完成。
- 是否取得正式报告。
- 报告是否上传。
- 报告有效期是否入库。
- 是否临期提醒。
- 是否存在不合格项。
- 不合格项是否整改复检。

### 3.2 重点外委

代表事项：

- 电梯维保。
- 中央空调主机维保。
- 智能化系统维保。
- 消防系统维保合同。
- 锅炉维保。
- 油烟管道、油烟机、净化器清洗。
- 厨房设备设施维保。
- 变电所维保。
- 舞台机械维保。

闭环重点：

- 合同是否有效。
- 服务商是否按计划进场。
- 维保记录是否上传。
- 现场照片是否留存。
- 验收人是否确认。
- 是否产生异常或整改项。
- 费用是否与预算匹配。

### 3.3 零星工程

代表事项：

- 合同外配件更换。
- 设备维修。
- 管道阀门维修。
- 冷却塔附属设施维修。
- 空调水系统维修。
- 消防报警系统配件更换。

闭环重点：

- 问题来源。
- 派工记录。
- 维修前后照片。
- 材料费用。
- 维修结果。
- 是否影响资产状态。

### 3.4 自行维保

代表事项：

- 内部工程人员自行完成的周期性保养、巡查、清洁、调试。

闭环重点：

- 谁执行。
- 何时执行。
- 是否按标准完成。
- 是否拍照留痕。
- 是否发现异常。

### 3.5 CAPEX / FFE

代表事项：

- 中大修。
- 更新改造。
- 资本性改造。
- 固定资产采购。

闭环重点：

- 立项。
- 预算。
- 审批。
- 采购。
- 施工。
- 验收。
- 转固。
- 资料归档。

## 6. 闭环逻辑修正

不同类型的事项闭环条件不同，不能全部按“拍照提交日报”处理。

### 6.1 强制检测闭环条件

必须满足：

- 任务已执行。
- 检测报告已上传。
- 报告有效期已录入。
- 检测结果已标记。
- 如有不合格项，已生成整改任务。
- 下次检测提醒已生成。

闭环后沉淀到：

- 证照报告台账。
- 资产台账。
- 年度计划执行记录。

### 6.2 重点外委闭环条件

必须满足：

- 服务商进场记录。
- 现场照片或维保记录。
- 内部责任人验收。
- 如产生配件或费用，记录实际金额。
- 如有异常，生成整改或复查任务。

闭环后沉淀到：

- 外委服务记录。
- 资产台账。
- 合同执行记录。

### 6.3 零星工程闭环条件

必须满足：

- 问题描述。
- 维修前照片。
- 维修后照片。
- 材料或费用记录。
- 使用部门/工程负责人确认。

闭环后沉淀到：

- 维修记录。
- 资产历史。
- 费用台账。

### 6.4 日常巡检闭环条件

仍沿用原系统逻辑：

- 照片满足要求。
- AI 识别完成。
- 人工确认字段。
- 提交巡检记录。
- 更新资产台账。
- 异常进入复核。

## 7. AI 能力修正

AI 不应只识别现场照片，还要处理工程计划表和执行资料。

### 7.1 Excel 导入时

AI 可以做：

- 自动识别计划类别。
- 从备注中提取周期。
- 识别责任人缺失。
- 识别预算缺失。
- 识别日期异常，例如开始时间晚于结束时间、年份异常。
- 自动生成任务拆分建议。

例子：

- “水质检测报告，备注每年 1 月、7 月检测”应拆成 1 月和 7 月两个检测任务。
- “军团菌检测，每年 1、4、7、10 月检测”应拆成季度任务。
- “排水系统排污检测，关注排污许可证到期时间”应生成证照到期关注任务。

### 7.2 执行过程中

AI 可以做：

- 识别上传报告是否对应当前事项。
- 从报告中提取有效期、检测结论、出具单位。
- 识别现场照片是否覆盖设备或施工范围。
- 比对维修前后照片，生成验收摘要。
- 对异常项目生成整改建议。

### 7.3 管理后台中

AI 可以回答：

- 本月哪些强制检测快到期？
- 哪些计划没有责任人？
- 哪些事项有预算但没有执行记录？
- 哪些外委事项即将到期？
- 哪些报告还没有上传？
- 哪些事项可能影响合规安全？

## 8. 状态体系修正

### 8.1 工程计划状态

| 状态 | 含义 |
| --- | --- |
| 未开始 | 计划窗口未到 |
| 待生成任务 | 到期前需要生成执行任务 |
| 执行中 | 已有任务在执行 |
| 待资料 | 执行完成但缺少报告/照片/验收资料 |
| 待验收 | 资料齐全，等待主管确认 |
| 已闭环 | 已完成并沉淀台账 |
| 已逾期 | 超过计划结束时间未闭环 |
| 已暂停 | 管理员暂停 |

### 8.2 执行任务状态

| 状态 | 含义 |
| --- | --- |
| 待执行 | 已派发但未开始 |
| 进行中 | 已开始执行 |
| 需补资料 | 缺少照片、报告、费用、签字 |
| 待验收 | 资料齐全，等待验收 |
| 异常待整改 | 检测不合格或现场异常 |
| 已闭环 | 完成全部闭环条件 |
| 已逾期 | 超过截止时间 |
| 已取消 | 明确取消原因 |

### 8.3 资料状态

| 状态 | 含义 |
| --- | --- |
| 未上传 | 没有资料 |
| 不完整 | 缺关键资料 |
| 待识别 | 文件已上传，AI 未提取 |
| 已识别 | AI 已提取要点 |
| 待确认 | 需要人工确认 |
| 已归档 | 资料正式入库 |

## 9. 页面设计修正建议

### 9.1 工程计划页

建议核心布局：

- 顶部：年度计划总览。
- 左侧：计划事项列表。
- 右侧：计划详情。
- 底部或抽屉：任务生成、资料、执行日志。

重点看板指标：

- 年度事项数。
- 本月到期。
- 临期证照。
- 逾期未闭环。
- 预算总额。
- 已闭环金额。

筛选条件：

- 类别。
- 责任人。
- 月份。
- 状态。
- 是否有预算。
- 是否缺责任人。
- 是否缺资料。

### 9.2 执行任务页

建议核心布局：

- 今日待办。
- 本周重点。
- 待资料。
- 待验收。
- 异常整改。
- 已闭环。

任务详情要显示：

- 来源计划。
- 工作内容。
- 执行要求。
- 责任人。
- 计划窗口。
- 预算。
- 上传资料。
- AI 提取结果。
- 验收结论。
- 关联资产。
- 状态流转。

### 9.3 证照报告台账页

建议后续新增。

核心字段：

- 报告名称。
- 报告类型。
- 关联计划事项。
- 出具单位。
- 有效期。
- 到期提醒。
- 文件附件。
- 检测结论。

这页对领导提问很有价值，因为强制检测的核心不是拍照，而是合规资料的到期和闭环。

## 10. 从 Excel 导入到系统的流程

建议流程：

```mermaid
flowchart LR
  A["上传年度工程计划 Excel"] --> B["系统解析 Sheet"]
  B --> C["生成工程计划事项"]
  C --> D["AI 提取周期/责任人/预算风险"]
  D --> E["人工确认导入结果"]
  E --> F["生成年度计划库"]
  F --> G["按月份生成执行任务"]
  G --> H["执行/上传资料/验收"]
  H --> I["更新台账与报告库"]
```

导入时应做校验：

- 缺责任人。
- 缺开始/结束时间。
- 缺预算但类别需要预算。
- 备注里有周期但未拆任务。
- 计划结束时间已过期。
- 同一工作内容重复。
- 责任人名称不统一。

## 11. 系统价值表达修正

结合真实计划后，项目亮点应从“拍照识别填报”升级为：

> 把年度工程计划、现场执行、检测报告、资产台账和异常整改串成一个闭环。

可以对外这样说：

传统工程计划常见问题是：Excel 里有计划，但执行过程散在微信群、纸质报告、现场照片和个人记忆里。到年底复盘时，很难快速回答“哪些检测到期了、哪些外委做完了、哪些报告没归档、哪些设备还有风险”。

智巡的升级方向，是把年度工程计划导入系统后，自动拆成执行任务；一线人员按任务完成拍照、检测、维保和资料上传；AI 辅助识别报告、照片和异常；主管只看闭环状态、临期风险和台账沉淀。这样计划不是停在 Excel 里，而是变成可执行、可追踪、可复盘的工程管理闭环。

## 13. 给 Claude 的落地建议

如果继续开发，建议按以下顺序：

1. 保留现有“巡检计划/巡检任务”菜单，但内部改成工程计划对象。
2. 新增后端表 `engineering_plan_items`、`engineering_tasks`、`engineering_reports`。
3. 先做 Excel 导入解析，把 `24年工程计划事项` 导入为计划事项。
4. 计划页先展示真实字段，不要再用假点位模板生成计划。
5. 任务页展示由计划事项生成的执行任务。
6. 强制检测任务优先支持“上传报告 + 有效期 + 验收闭环”。
7. 重点外委任务优先支持“维保记录 + 现场照片 + 验收闭环”。
8. 移动端仍保留拍照识别，但作为任务证据采集入口，不再是唯一入口。

## 14. 修正后的一句话定位

智巡不是单纯的拍照巡检工具，而是把年度工程计划从 Excel 变成任务，把现场执行变成证据，把检测报告变成台账，把异常整改变成闭环的工程管理系统。
