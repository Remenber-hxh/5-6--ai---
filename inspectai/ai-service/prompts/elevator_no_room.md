# 无机房电梯巡检（视觉合规检查）

> 适用模板：`elevator_no_room`（电梯巡检（无机房））
> 无机房电梯**没有独立机房**，只查轿厢与层站现场。
> 输入图片：1-6 张，常见为 —— 轿厢操作面板（楼层按钮/显示屏、警铃/对讲、消防返回开关）、轿厢与候梯厅照明、层门、《特种设备使用标志》/登记证、轿厢编号牌。
> 任务定位：视觉合规检查，只把照片里**能确认的事实**变成字段，不做维修结论，不默认现场正常。

## 总则
- 选项字段全部是 `["是","否"]`：**是 = 符合要求 / 完好 / 正常**；**否 = 不符合 / 缺失 / 破损 / 异常 / 过期**。
- **直接可见项要主动判断，不要为"求稳"留空**：登记标志、操作面板/楼层按钮与显示、轿厢/候梯厅照明、消防开关玻璃、报警装置是否在位完好——相关画面拍清楚就给"是/否"，明显正常/完好就大胆判"是"（少量灰尘/反光不算异常）。
- 「轿门防夹人装置有效」「开关门运行无卡阻」是**现场测试项**：巡检员会当场测试并拍下来（如把手/物体伸到轿门口测防夹、把门开到位）——**照片拍到测试动作或门的开合状态，就按门的实际响应判"是/否"**；只有完全没拍到相关画面才不返回留人工，不要因为"是功能项"就一律留空。
- **其余画面里出现的项一律主动给"是/否"，不得为"求稳"留空**：装置、标识、按钮、照明、玻璃看外观与点亮状态。
- 照片无法感知声音/气味；无可见证据的此类项不返回。
- 真的看不清、没拍到、角度不够才不返回，不要用"否"代替"没拍到"。
- 关键照片缺失可在 `nonconformity` 写"建议补拍 XX"，但缺照片 ≠ 设备异常。

## 字段映射
| code | label | 判断依据（看到什么才给值） |
| --- | --- | --- |
| `inspection_time` | 日期 | 系统注入，不返回 |
| `asset_no` | 电梯编号 | 仅当编号牌/《特种设备使用标志》单位内编号**清晰可读**时返回；模糊或推断则不返回 |
| `inspector` | 检查人 | 系统注入，不返回 |
| `reg_mark` | 电梯使用登记标志完好 | 《特种设备使用标志》/登记证在位、信息完整清晰、未破损褪色、未过下次检验日期 → 是；缺失/破损/字迹不清/过期 → 否；未拍到 → 不返回 |
| `alarm_device` | 紧急报警装置有效 | 轿厢内警铃按钮/五方对讲装置**在位且外观完好** → 是；装置缺失、按钮破损脱落 → 否；未拍到 → 不返回。（注：只判在位+完好，按下是否真响属功能测试，照片不强求） |
| `anti_clip` | 轿门防夹人装置有效 | 照片拍到防夹测试动作——有人把手/物体伸入轿门关闭路径(门边/门口)，门未夹住、保持开启或遇阻回弹 → 是；明显夹住手/物体不回弹 → 否；只有静态门照、无任何测试动作 → 不返回（留人工） |
| `door_smooth` | 开关门运行无卡阻 | 轿门/层门完全打开到位、门体平整无变形错位、地坎/门槽无杂物卡阻（含开门测试照）→ 是；门体变形/错位/门缝明显不均/卡滞/有杂物卡阻 → 否；未拍到门 → 不返回 |
| `floor_buttons` | 选层按钮及显示正常 | 轿厢操作面板楼层按钮齐全无缺损、楼层显示屏点亮且数字正常 → 是；按钮缺损、显示黑屏/乱码 → 否；未拍到面板 → 不返回 |
| `car_lighting` | 候梯厅、轿厢内照明正常 | 轿厢内/候梯厅照明点亮、明亮均匀 → 是；明显熄灭、大面积不亮 → 否；未拍到 → 不返回 |
| `fire_switch_glass` | 消防开关玻璃完好 | 消防返回开关的玻璃罩/保护盖完好、未破碎 → 是；玻璃破损/缺失/已击碎 → 否；未拍到 → 不返回 |
| `nonconformity` | 不符合项处理情况记录 | 仅在发现异常、或关键部位未拍到时填一句简短说明（<40字） |

## 输出
严格遵循 `_common.md` 的 JSON schema：`recognitionStatus` / `observations`（按图顺序）/ `recognizedFields`（只放有视觉依据的字段，code 必须完全等于上表，choice 值只能是 `"是"`/`"否"`）/ `warnings`。

## 置信度
- 0.90-0.98：标识/装置/按钮/显示清晰、证据充分。
- 0.70-0.89：可判断但有反光、角度或轻微遮挡，需人工快速复核。
- 低于 0.70：不返回该字段。
