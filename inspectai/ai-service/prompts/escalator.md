# 自动扶梯 / 自动人行道巡检（视觉合规检查）

> 适用模板：`escalator`（扶梯巡检）
> 输入图片：1-6 张，常见为：出入口与警示标识、梳齿板/梯级、扶手带、护壁板、安全毛刷、上下基坑盖板、紧急制动开关、《安全检验合格》标志/登记牌等部位。
> 任务定位：视觉合规检查，只把照片里**能确认的事实**变成字段，不做维修结论，不默认现场正常。

## 总则
- 选项字段全部是 `["是","否"]`，**按字段的问句字面回答**：
  - "……是否完好 / 正常 / 牢固 / 完整 / 有效"：完好/正常 → **是**；破损/异常/缺失 → **否**。
  - "扶梯运行**是否有异响**"：方向相反——有异响 → **是**(异常)；无异响 → **否**(正常)。
- **直接可见项要主动判断，不要为"求稳"留空**：警示标识、梳齿板/梯级、扶手带、护壁板、安全毛刷、基坑盖板、急停按钮、《安全检验合格》标志——相关部位拍清楚就给"是/否"，明显完好就大胆判"是"。
- 只有照片能明确支持时才给值；看不清、没拍到、角度不够 → **不返回该字段**，交人工，不要拿"是/否"代替"没拍到"。
- 照片**无法感知声音、运行速度、装置是否真正有效**——这类没有可见证据时不返回。
- 关键照片缺失可在 `nonconformity` 写"建议补拍 XX"，但缺照片 ≠ 设备异常。

## 字段映射
| code | label | 判断依据（看到什么才给值） |
| --- | --- | --- |
| `inspection_time` | 检查时间 | 系统注入，不返回 |
| `asset_no` | 扶梯编号 | 仅当编号牌/标志上的编号清晰可读时返回 |
| `inspector` | 巡检人员 | 系统注入，不返回 |
| `entrance_sign` | 出入口警示标识是否完好 | 出入口警示标识齐全、完好 → 是；缺失/破损/污损不可读 → 否 |
| `anti_climb` | 防档防攀爬是否完好 | 防攀爬挡板/装置在位完好 → 是；缺失/变形/损坏 → 否 |
| `emergency_stop` | 紧急制动开关是否正常 | 急停按钮在位、完好、无遮挡 → 是；缺失/损坏/被挡 → 否；"是否正常"需实测的部分无可见依据 → 仅按可见状态给 |
| `comb_plate` | 疏齿板是否牢固、齿是否完整 | 梳齿板齿形完整、无缺齿/断齿、安装牢固 → 是；缺齿/断裂/翘起 → 否 |
| `steps` | 梯级是否完好 | 梯级踏板完好、无破损/塌陷/缺失、无异物卡阻 → 是；破损/缺失/明显磨损 → 否 |
| `pit_cover` | 上、下基坑盖板是否牢固 | 上下基坑盖板齐全、平整、牢固 → 是；缺失/翘起/松动 → 否；未拍到 → 不返回 |
| `handrail` | 扶手带是否完好 | 扶手带表面完好、无破损/裂口 → 是；破损/老化开裂 → 否 |
| `skirt_panel` | 扶梯护壁板是否牢固 | 护壁板/裙板完整、无变形、安装牢固 → 是；破损/缺失/松动 → 否 |
| `safety_brush` | 安全毛刷是否完好 | 裙板安全毛刷齐全、完好 → 是；缺失/脱落/损坏 → 否 |
| `running_speed` | 扶梯运行速度是否正常 | 速度需现场观测，照片通常无法判定 → 不返回；仅当照片明确显示停运/异常时给"否" |
| `running_noise` | 扶梯运行是否有异响 | 照片不能感知声音 → 通常不返回；仅当看见可致异响的可见故障（部件松脱/卡阻）才给"是" |
| `inspection_cert` | 《安全检验合格》标志是否完好 | 《安全检验合格》标志在位、完好、在有效期内 → 是；缺失/破损/已过期 → 否 |
| `nonconformity` | 不符合项说明 | 仅在发现异常或关键部位未拍到时填简短说明（<40字） |

## 输出
严格遵循 `_common.md` 的 JSON schema：`recognitionStatus` / `observations`（按图顺序）/ `recognizedFields`（只放有视觉依据的字段，code 必须完全等于上表，choice 值只能是 `"是"`/`"否"`）/ `warnings`。

## 置信度
- 0.90-0.98：部位清晰、证据充分。
- 0.70-0.89：可判断但有反光、角度或轻微遮挡，需人工快速复核。
- 低于 0.70：不返回该字段。
