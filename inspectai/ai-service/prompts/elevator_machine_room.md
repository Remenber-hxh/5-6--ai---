# 有机房电梯巡检（视觉合规检查）

> 适用模板：`elevator_machine_room`（电梯巡检（有机房））
> 输入图片：1-6 张，常见为以下场景的组合 ——
> 1. 电梯机房门（挂「电梯机房 / ELEVATOR MACHINE ROOM」标识、防火门）
> 2. 机房内部（曳引机、控制柜、限速器、盘车手轮 / 松闸扳手 / 救援说明牌、机房空调温控器、火警电话）
> 3. 机房地面与环境（是否干净、有无杂物堆放）
> 4. 轿厢操作面板（楼层按钮、开关门、警铃、消防返回开关）
> 5. 层站 / 厅门（消火栓、防夹与禁止倚靠警示标识、小心地滑）
> 6. 特种设备使用标志（登记证、单位内编号、下次检验日期）、救援电话牌
> 7. 灭火器（瓶体、压力表指针、检查记录卡、合格证 / 有效期）
> 任务定位：视觉合规检查，只把照片里**能确认的事实**变成字段，不做维修结论，不默认现场正常。

## 总则

- 选项字段全部是 `["是","否"]`：**是 = 符合要求 / 完好 / 正常**，**否 = 不符合 / 缺失 / 破损 / 异常 / 过期**。
- **直接可见项要主动判断，不要为"求稳"留空**：机房门窗/警示标识、机房清洁度、照明与空调、灭火器在位、救援装置（盘车手轮/松闸扳手/救援说明牌）是否齐全——相关画面拍清楚就给"是/否"，明显正常/完好就大胆判"是"（少量灰尘/反光不算异常）。
- 只有照片能明确支持时才给值;看不清、没拍到、角度不够 → **不返回该字段**，留给人工复核，不要用「否」来代替「没拍到」。
- 照片**无法感知声音和气味**。涉及异响/异味的项，没有可见证据时一律不返回。
- **照片只能确认"在不在 / 完不完好 / 亮不亮"，无法确认"功能是否有效"**：需要现场操作才能验证的**功能性测试项**（轿门防夹人装置是否有效、开关门运行是否卡阻等"动作类"项）——**一律不返回，留人工**，绝不能凭外观猜"是"。
- 关键照片缺失可在 `nonconformity` 里写"建议补拍 XX"，但缺照片 ≠ 设备异常。

## 字段映射

| code | label | 判断依据（看到什么才给值） |
| --- | --- | --- |
| `inspection_time` | 日期 | 系统注入，不返回 |
| `asset_no` | 电梯编号 | 仅当「特种设备使用标志」上的"单位内编号"或轿厢编号牌**完整清晰可读**时返回（如 K07）；模糊或推断则不返回 |
| `inspector` | 检查人 | 系统注入，不返回 |
| `door_window_sign` | 机房门窗、警示标识完好 | 看到机房门完好关闭、门上「电梯机房」标识及「危险/未经许可禁止入内/禁止攀爬」等警示标识齐全完好 → 是；标识缺失、破损、门损坏 → 否 |
| `room_clean` | 机房干净无杂物 | 机房地面整洁、无明显杂物/积水/易燃堆放 → 是；地面脏乱、堆放杂物、漏油积水 → 否 |
| `lighting_ac` | 机房照明及空调正常 | 机房照明明亮，且空调/温控器在运行（如温控器亮屏显示温度、制冷标志，室温约 18-27℃）→ 是；明显无照明、空调黑屏/不工作/温度异常偏高 → 否 |
| `extinguisher_valid` | 灭火器材未过期 | 看到灭火器**压力表指针在绿区**、且合格证/检查记录卡上的有效期或生产日期未过期 → 是；指针在红区（欠压/超压）、或有效期已过、或检查记录长期空缺 → 否；只拍到瓶体看不到压力表和日期 → 不返回 |
| `noise_smell` | 设备无异响、异味 | 照片不能感知声音气味；仅当能**看见**明确异常（曳引机漏油、线缆烧焦痕迹、部件松脱）才返回"否"，否则不返回，交人工现场判断 |
| `rescue_device` | 紧急救援设备装置齐全 | 看到机房内盘车手轮、松闸扳手、救援说明牌三者齐备且就位 → 是；明显缺失某项 → 否；未拍到该区域 → 不返回 |
| `reg_mark` | 电梯使用登记标志完好 | 看到「特种设备使用标志/登记证」标牌在位、信息完整清晰、未破损褪色 → 是；标牌缺失/破损/字迹不清 → 否；未拍到 → 不返回 |
| `alarm_device` | 紧急报警装置有效 | 轿厢内报警按钮（警铃）/五方对讲装置**在位且外观完好** → 是；装置缺失、按钮破损脱落 → 否；未拍到 → 不返回。（注：只判在位+完好，按下是否真响属功能测试，照片不强求） |
| `anti_clip` | 轿门防夹人装置有效 | **功能性测试项，静态照片无法判断（需关门动作验证光幕/触板）→ 一律不返回，留人工**，不要凭外观猜 |
| `door_smooth` | 开关门运行无卡阻 | **动作类测试项，静态照片无法判断开关门是否顺畅 → 一律不返回，留人工** |
| `floor_buttons` | 选层按钮及显示正常 | 轿厢操作面板楼层按钮齐全无缺损、楼层显示屏点亮且数字正常 → 是；按钮缺损、显示黑屏/乱码 → 否；未拍到面板 → 不返回 |
| `car_lighting` | 候梯厅、轿厢内照明正常 | 轿厢内 / 候梯厅照明点亮、明亮均匀 → 是；明显熄灭、大面积不亮 → 否；未拍到 → 不返回 |
| `fire_switch_glass` | 消防开关玻璃完好 | 消防返回开关的玻璃罩 / 保护盖完好、未破碎未击碎 → 是；玻璃破损/缺失/已击碎 → 否；未拍到 → 不返回 |
| `nonconformity` | 不符合项目处理情况记录 | 仅在发现异常、或关键部位未拍到时填一句简短说明（<40字） |

## 输出

严格遵循 `_common.md` 的 JSON schema：`recognitionStatus` / `observations`（按图顺序）/ `recognizedFields`（只放有视觉依据的字段，code 必须完全等于上表）/ `warnings`。choice 值只能是 `"是"` 或 `"否"`。

示例片段（仅示意，不要照抄数值）：

```json
{
  "recognitionStatus": "recognized",
  "observations": ["图1：电梯机房防火门关闭，门上挂"电梯机房"铭牌与禁止攀爬警示标识，完好", "图2：机房墙面挂盘车手轮、松闸扳手、救援说明牌"],
  "recognizedFields": [
    { "code": "door_window_sign", "value": "是", "confidence": 0.9, "reason": "图1机房门及警示标识齐全完好" },
    { "code": "rescue_device", "value": "是", "confidence": 0.88, "reason": "图2盘车手轮/松闸扳手/救援说明三件齐备" }
  ],
  "warnings": []
}
```

## 置信度

- 0.90-0.98：标识/装置/压力表清晰、证据充分。
- 0.70-0.89：可判断但有反光、角度或轻微遮挡，需人工快速复核。
- 低于 0.70：不返回该字段。
